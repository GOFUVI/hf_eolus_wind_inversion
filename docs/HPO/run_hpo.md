# Hyperparameter Tuning Pipeline

Hyperparameter optimisation (HPO) refers to the systematic search for the hyperparameter configuration that maximises a model’s out-of-sample skill. Rather than relying on manual trial-and-error, the procedure formalises the exploration of learning rates, regularisation strengths, network capacity, and auxiliary loss weights, evaluating each candidate on a validation surrogate and iterating towards the optimum. In the context of the HF-radar wind inversion system, HPO is the mechanism that reconciles regression accuracy with the physical range-classification constraints, ensuring that the neural architecture generalises beyond the training split while respecting the gating rules imposed by the observing system.

## Overview
The SAR wind inversion model uses AWS SageMaker Hyperparameter Tuning Jobs (HPO) to explore learning rates, architecture depth/width, regularisation, and the range-aware loss knobs shared with the training pipeline. The entry point `scripts/HPO/run_hpo.sh` packages the code (via `Dockerfile.hpo`), generates a tuning configuration from `artifacts_root/sar/config/sar_hpo.json`, and launches SageMaker trials that each run cross-validation with `cv_train.py`.

Beyond preparing the tuning payload, the launcher automates the surrounding cloud plumbing. Unless an existing image URI is supplied, it builds the Docker image locally, pushes it to ECR, and provisions or refreshes a SageMaker execution role with the required S3, ECR, and CloudWatch policies. Before submission it validates that the declared training and output prefixes are reachable, sanitises the job name, and writes both the generated configuration JSON and a timestamped activity log under the chosen `--log-dir`. After dispatching the job, it polls SageMaker every 60 seconds and, once the tuner finishes, invokes `scripts/HPO/hpo_metrics_report.sh` to emit a per-job Markdown summary.

Configuration assets now live under `artifacts_root/<model>/config`, keeping every model's search space, base hyperparameters, and derived artefacts together with its reports.

Key assets:
- `artifacts_root/sar/config/sar_hpo.json` – canonical search space definition.
- `run_hpo-config.json` – example SageMaker request payload generated by `run_hpo.sh` (useful for inspection or manual submission).
- `scripts/HPO/` – tooling for launching jobs, collecting metrics, and hydrating best-model configs.

The generated `<job_name>_hpo_report.md` and `run_hpo.log` files reside in the log directory passed via `--log-dir` (the current directory by default), keeping request metadata, console traces, and fold metrics together for auditability.

## Combined Loss Objective
`train_lib/reporting.py` prints a macro-F1–aware combined loss for every trial:

```
CombinedLoss = w_speed * MSE_speed + w_angle * MSE_angle + λ * (1 - macro_F1)
```

- `w_speed`, `w_angle` are the DWA weights carried over from training.
- `λ = range_loss_weight` is the classification penalty sampled by HPO.
- `macro_F1` comes from the range-classification head.

This formulation keeps the tuner focused on in-range regression quality **and** range-classification skill. Reports include the same metric so you can filter candidates by CombinedLoss plus business thresholds on macro-F1 or accuracy.

## Search Space Highlights
- **Range-aware knobs:** `range_loss_weight`, `range_margin`, and `range_flag_threshold` let HPO balance the classification head against regression.
- **Network width:** `hidden_units` values now include `{64, 128, 256, 512, 768}`, allowing the tuner to grow the MLP before increasing depth.
- **Core parameters:** learning rate (log scale), hidden layer count, dropout, batch size, weight decay, patience, MAD/median velocity toggles, and aggregation statistic remain available.

Update `artifacts_root/sar/config/sar_hpo.json` to refine ranges; `run_hpo.sh` will propagate the changes when regenerating the SageMaker request.

## Preconditions
Ensure the local and AWS environments satisfy the following conditions before triggering the pipeline, otherwise `run_hpo.sh` will abort during its validation preflight:
- The AWS CLI profile used for the run has permissions to create or update SageMaker tuning jobs, manage IAM roles and policies, interact with ECR, and read/write to the targeted S3 prefixes.
- Docker is available on the host so the launcher can build and tag the HPO container image specified by `Dockerfile.hpo`.
- `jq` is installed; the script relies on it to parse model and search-space JSON files.
- The model definition referenced via `--model-config` enumerates at least two stations; the wrapper stops early if the station list is shorter.
- The S3 URIs provided through `--train-data-uri` and `--output-s3-uri` exist and are reachable from the execution role; the script simulates policy access before submitting the job.
- When configuration regeneration is enabled (the default), `--hpo-config` must point to the search-space file; omit it only if you pass `--update-config false` and reuse an existing JSON.

## Typical Workflow
1. Update `artifacts_root/sar/config/sar_hpo.json` with the desired search space.
2. Launch HPO:
   ```bash
   bash scripts/HPO/run_hpo.sh \
     --profile your_profile \
     --job-name sar-hpo-job-b-1 \
     --train-data-uri s3://.../training/sar/train/ \
     --output-s3-uri s3://.../models/sar \
     --model-config artifacts_root/sar/config/sar_model.json \
     --hpo-config artifacts_root/sar/config/sar_hpo.json
   ```
3. Monitor progress with `aws sagemaker describe-hyper-parameter-tuning-job`.
4. Inspect the automatically generated per-job report `<log_dir>/<job_name>_hpo_report.md`; when comparing several campaigns, aggregate them with `scripts/HPO/integrate_hpo_reports.sh`.
5. Extract the best trial and produce a ready-to-train model JSON with `scripts/training/generate_model_config_from_hpo.sh`.

## Tips
- Ensure the training partition is balanced across `wind_bin` (see the partition report) so cross-validation reflects every regime.
- When extending the search space, keep trial budget in mind—adding width or range parameters increases the dimensionality and may require more jobs or warm starts.
- Use the “Fold Balance Checks” section in `artifacts_root/sar/reports/partition/pivots_sar_partition_report.md` to confirm partitions remain equitable before relaunching HPO.
